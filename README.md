# AI Roundtable — Multi-Agent Collaboration

本地运行、MIT 开源的多智能体圆桌协作桌面应用。基于 **@earendil-works/pi-coding-agent 1.4.0** 的真实 AgentSession，非多模型轮流聊天。各成员独立推理、主动定向提问、委派、领取共享任务、交付文本成果。实际测试记录见 [VERIFICATION.md](VERIFICATION.md)。

## 桌面版启动（推荐）

Windows 成品位于 `release/AI-Roundtable-0.4.0-win-x64.zip`，运行时不要求另装 Node.js、浏览器或任何启动脚本。

1. 在资源管理器中右键 `AI-Roundtable-0.4.0-win-x64.zip`，点击“全部解压”，再点击“提取”。不要直接在压缩包预览窗口中运行程序。
2. 打开解压得到的文件夹，双击 `AI Roundtable.exe`。重复双击不会启动第二套后端，而会切回现有窗口。
3. 本地构建没有购买代码签名证书。如果 Windows 首次显示“Windows 已保护你的电脑”，确认文件来自本项目后点击“更多信息”，再点击“仍要运行”。
4. 正常退出时直接点击窗口右上角“×”。桌面进程会先中止在途请求、收尾 Pi Session、关闭 SQLite，再退出全部子进程；不需要另外停止服务。
5. 桌面数据保存在 `%APPDATA%\AI Roundtable\data`。第一次启动时，如果发现旧项目 `data/` 或旧桌面数据，应用会先优雅停止旧服务，再复制聊天、成果、Session 和加密凭据；不会覆盖已经初始化的新数据。

## 源码开发模式

源码开发需要 Node.js 22.19.0+（Pi SDK 1.4.0 的最低要求；本机验证版本 24.22.1）。

1. 在项目文件夹空白处右键，点击“在终端中打开”。
2. 输入 `npm ci` 安装依赖。
3. 输入 `npm run desktop` 启动 Electron 桌面开发版；关闭窗口即完成保存和停止。

## 配置与使用

> 从旧版升级时，历史工作区、Agent 和模型会自动迁移。旧版从未将 API Key 写入磁盘，因此升级后需要在“配置中心”为每个接入重新输入一次密钥。之后密钥会加密保存，无需每次重填。

1. 点击左下角“配置中心”，按页面顺序先添加“接入配置”。填写名称、API 基础地址、协议和认证方式。Agnes 的基础地址为 `https://api.agnes-ai.cn/v1`，协议为 `openai-completions`。
2. 在接入配置中填写 API Key 并保存。Windows 使用当前用户 DPAPI，macOS 使用 Keychain，Linux 使用 Secret Service（需安装 `secret-tool`）。桌面版的 `%APPDATA%\AI Roundtable\data\credentials.enc` 只保存密文或凭据库标记，明文不会进入 SQLite、界面状态、源码或日志。也可以只填写环境变量名。修改 API 地址、协议或认证方式时，需要重新输入密钥，防止旧密钥被发往新地址。
3. 在“接入配置”的已保存项右侧点击“模型目录”，可从供应商读取模型；也可在下方“模型”区域点击“添加模型”手动填写。分别设置显示名称、模型 ID、上下文长度和输出上限。接入凭据可供同一服务下的多个模型复用。
4. 在“Agent 身份”区域设置名称、职责、默认模型和成果权限。身份、接入和模型互相独立；多个 Agent 可以使用同一模型，同一 Agent 也能在工作区中切换模型。
5. 点击“新建工作区”，填写名称、勾选至少两个成员，点击“创建工作区”。每个工作区为每位成员新建独立 Pi Session。
6. 在底部输入任务，选择“@ 全体成员”或指定成员，点击“发送”。可要求设计师主动向评审员请求检查。带“定向交接”的消息来自真实 `send_message` 工具调用。
7. 右侧查看成员状态、任务板和成果。点击成果时才按需读取正文，可阅读 Markdown 预览或点击“下载文本”保存原文。聊天支持标题、粗体、斜体、列表、引用和代码块；先进行 HTML 转义，不执行模型输出的 HTML 或脚本。
8. “暂停”中止当前请求并保留等待队列；暂停期间仍可发送修正意见，然后点击“继续”。“终止”中止请求并清空队列。已执行的工具和已产生的成果不会撤销。达到预算后，点击右侧“调整”增加预算，再点击“继续”。
9. 在右侧成员卡片的下拉菜单中选择其他模型，即可在同一个对话中切换。切换会写入一条系统记录；该成员的 Pi Session 文件、上下文水位、任务和历史均保持不变。成员正在生成时需先点击“暂停”。
10. 左侧点击历史工作区即可恢复查看。消息每次读取最近 100 条，点击顶部“加载更早消息”分页读取。重启后不会自动恢复执行；点击“继续”显式恢复。需要清理时，点击顶部“删除”并在确认框中确认，会删除该工作区的消息、任务、成果和 Pi Session。

## 架构

```text
Electron BrowserWindow（原生 ES modules / CSS）
  ├─ 点击“×” → 等待工作区收尾 → 关闭内嵌服务和桌面进程
  ├─ POST：消息、运行控制、配置、预算
  └─ SSE：仅推送新消息 / 单工作区元数据 / 流式片段
       │
内嵌 Node.js HTTP 服务（仅随机 127.0.0.1 端口）
       │
事件驱动调度器 ── SQLite WAL
  ├─ 小型元数据快照：配置 / 队列 / 成员状态 / 任务
  ├─ messages：每条消息单独追加、按序号分页
  ├─ artifacts：正文独立存储、按需读取
  └─ effects：只保存有副作用工具的紧凑幂等结果
  ├─ Agent A → 独立 Pi AgentSession → 模型服务 A
  ├─ Agent B → 独立 Pi AgentSession → 模型服务 B
  └─ Agent N → 独立 Pi AgentSession → 模型服务 N
       └─ 各自 Pi JSONL：私有上下文、压缩摘要、工具结果、同步水位
```

- `src/engine.mjs`：定向投递、去重、单 Agent 串行、工作区并发、全局并发、运行边界与工具。
- `src/pi-session.mjs`：原生 Pi SessionManager 恢复、相对 Session 路径、DefaultResourceLoader、自动压缩、3 次指数退避和请求节流。Pi 1.4.0 没有公开每请求调度钩子，唯一的 `streamFunction` 兼容层已集中隔离并有形状检查。
- `src/secrets.mjs`：Windows DPAPI、macOS Keychain 和 Linux Secret Service 凭据后端；明文只在服务进程内存和发往所选 API 的请求中存在。
- `src/store.mjs`：Node 原生 SQLite，WAL + FULL 同步；消息、成果正文和工具幂等结果按行存储，不进入元数据快照。
- `src/http-utils.mjs`：UTF-8 流式请求解码、体积限制和统一输入校验。
- `server.mjs`：HTTP / SSE、输入校验、同源与 Host 检查、CSRF token、静态资源与 API。
- `desktop/`：Electron 单实例窗口、桌面数据迁移、外部导航隔离和关闭时的优雅收尾。
- `public/`：无需构建、无 CDN 的响应式 Web 客户端。

用户消息唤醒指定成员或全体。Agent 的 `send_message` 唤醒其选择的目标，调度器不决定讨论顺序，也不自动轮询模型。普通最终回复仅显示而不广播唤醒，避免每一句话引发所有成员回复。无待办事件时自然静止，不进行后台自我思考。

共享消息具有单调序号，写入时只向 `messages` 追加一行。每次激活直接从 SQLite 读取该 Agent 水位后的一批消息。同步标记写入 Pi 用户消息，恢复时从原生日志重建水位。Session 路径相对 `data/` 保存；搬移项目后仍可恢复，文件缺失时会明确报错，不会静默创建空上下文。

工具：

| 工具 | 行为 |
|---|---|
| `send_message` | 主动提问、委派、反馈，目标可为单个队友或 all |
| `task_board` | 创建、原子领取、完成、列出任务；只有负责人能完成 |
| `save_artifact` | 可选权限，创建不可覆盖文本成果，保存在 SQLite |
| `read_artifact` | 查看同一工作区成果列表或正文 |

工具以 Agent ID + Pi toolCallId 去重。只有可能改变状态的工具保存幂等结果；`read_artifact` 可安全重读，不会把成果正文复制进 `effects`。所有工具变更在单线程同步段执行，领取冲突不会双重成功。

## 运行限制

- 工作区 2–8 名成员，最多 30 个接入、100 个模型、30 个 Agent 身份和 100 个工作区；每个工作区最多 100 个任务和 100 个成果。
- 全局最多 4 个激活，每个工作区 1–4 个，同一个 Agent Session 不并发执行。
- 默认 24 次激活 / 60000 tokens；每次激活最多 8 次模型请求、16 次工具调用。
- 新建 Agnes 接入默认 65,000ms 请求间隔，其他远程服务建议 2,000ms；429、过载和瞬时服务错误由 AgentSession 最多自动重试 3 次，使用 2s / 4s / 8s 指数退避。供应商库内部重试已关闭，避免双层重试放大请求数。
- 激活时限为 120 秒加 8 个配置的请求间隔。等待节流或退避时可取消。
- Token 是服务商上报的会话用量；正在运行的并发请求、自动压缩和服务商统计差异可能产生超额。这不是精确账单硬限额。
- 保存的 API Key 只能由保存它的操作系统用户凭据库解密。删除 `data/credentials.enc` 会清除工作区对这些密钥的引用，不影响聊天和模型配置。
- 多 Agent 不天然节省 Token。简单任务建议在输入框上方只选择一位成员；只有需要独立审查、分工或异构模型时才唤醒队友。

## 验证命令

```powershell
npm run check
npm run package:win
```

`npm run check` 对桌面主进程、服务端、存储、引擎、Pi 适配层和界面入口执行语法检查。`npm run package:win` 会先运行检查，再生成 ZIP 桌面发行包。Pi SDK 保持精确锁定 `1.4.0`；升级依赖前必须重新执行完整回归和真实界面验收。

## 已知局限

Windows EXE 是本地未签名构建，首次运行可能触发 SmartScreen；发布给其他用户前应购买代码签名证书并配置 CI 签名。Electron 发行包约 165MB，因为包含 Chromium 和 Node.js 运行时。生产依赖使用安全覆盖后的 `undici 8.12.3`，`npm audit --omit=dev` 为 0 项。

这是本地单用户版本，没有团队登录、远程部署、文件执行沙箱、网络搜索、Shell、MCP 管理或多人权限。适用于讨论、方案审查和文本交付，不能宣称已经执行外部代码或修改用户文件。若要添加执行能力，应在独立隔离进程中实现权限、审批和资源限制。

Pi 日志和 SQLite 不共享同一个事务。正常停止、恢复及工具幂等有覆盖，但系统在两次持久化之间断电时，不保证跨存储严格 exactly-once；尤其最终文本可能已经进入 Pi 而尚未进入共享消息表。不会自动重放不确定的外部副作用。

SSE 断线重连后根据本地最后序号补拉已提交消息，断线期间尚未提交的文本片段不回放。Markdown 是安全子集，尚无表格、任务列表、语法高亮、图片输入和附件上传。

自动压缩通过 SDK 配置启用；真实溢出压缩、压缩失败后的所有恢复分支、非 OpenAI 兼容协议尚未全部进行真实模型验证。配置中的模型 ID 代表服务商接口标识，不证明其背后模型供应商或架构。
